# Prompt Codex — Création complète de Dogflix

Tu es un agent Codex chargé de concevoir, développer, tester et préparer au déploiement un site web complet appelé **Dogflix**.

Travaille de manière autonome de bout en bout. Ne te contente pas d’un prototype, d’une maquette ou d’un simple squelette : livre un projet fini, soigné, fonctionnel et prêt à être déployé. Ne demande pas de précisions supplémentaires ; lorsqu’un détail mineur manque, prends la décision la plus cohérente avec le cahier des charges.

## 1. Concept

**Dogflix** est une parodie ultra-humoristique de Netflix dans laquelle tous les films, toutes les séries et tous les personnages sont remplacés par des chiens.

Référence conceptuelle : <https://www.championcat.cl/catflix/>

Le résultat doit toutefois être beaucoup plus complet : il doit donner l’impression d’utiliser une véritable plateforme de streaming premium consacrée aux chiens, avec une forte densité de contenu, des interactions crédibles et de nombreux détails comiques.

## 2. Direction artistique et expérience

Reproduis avec une très grande fidélité l’expérience visuelle de Netflix :

- fond presque noir, surfaces anthracite et rouge vif caractéristique ;
- en-tête fixe et transparent au-dessus du hero, puis opaque pendant le défilement ;
- logo texte **DOGFLIX** en rouge, créé en HTML/CSS ou en SVG original ;
- navigation : `Accueil`, `Séries`, `Films`, `Nouveautés`, `Ma liste` ;
- grand hero cinématographique avec dégradés sombres, titre, accroche, description et boutons `Lecture` et `Plus d’infos` ;
- rangées horizontales de vignettes au format affiche ou paysage ;
- flèches de navigation, défilement fluide, indicateurs et effets de survol ;
- vignette agrandie au survol sur ordinateur avec actions, pourcentage de compatibilité, âge, durée et genres ;
- modal riche lorsqu’une œuvre est sélectionnée ;
- transitions et micro-interactions fluides ;
- responsive irréprochable sur mobile, tablette et ordinateur ;
- écran de sélection de profil au premier chargement avec quatre profils canins amusants ;
- favicon original en forme de patte ou de lettre `D` ;
- footer complet avec le texte `Dogflix est une parodie indépendante. Aucun chien n’a été forcé à binge-watcher.`

La fidélité concerne la structure, le rythme visuel et l’ergonomie d’une plateforme de streaming. N’utilise aucun logo, fichier, capture d’écran, photo d’acteur ou asset officiel appartenant à Netflix ou aux œuvres parodiées. Toute l’identité visible doit être originale et clairement attribuée à Dogflix.

## 3. Ton humoristique

L’intégralité de l’interface est en **français**. Le ton doit être absurde, tendre, malin et rempli de références au comportement des chiens : croquettes, friandises, balles, facteurs, chats, aspirateurs, promenades, canapés, laisses et vols de chaussettes.

Les textes doivent être drôles sans sembler générés à la chaîne. Ajoute des petits détails humoristiques dans les badges, les genres, les messages de chargement, la recherche vide, le faux lecteur et les métadonnées.

## 6. Données et catégories

Toutes les données doivent être écrites en dur dans un fichier TypeScript local clairement structuré. Il n’y a ni backend, ni base de données, ni CMS, ni authentification, ni API externe.

Chaque entrée doit contenir au minimum :

- identifiant et slug ;
- type `film` ou `serie` ;
- titre parodique et titre original de référence ;
- synopsis humoristique ;
- année fictive ou cohérente ;
- durée pour un film ou nombre de saisons pour une série ;
- classification d’âge ;
- pourcentage de compatibilité Dogflix ;
- trois genres humoristiques ;
- chemins locaux de l’affiche et du backdrop ;
- propriétés permettant d’indiquer `nouveau`, `tendance`, `exclusivité Dogflix` et `dans ma liste`.

Répartis le catalogue dans plusieurs rangées, sans toujours conserver le même ordre :

- Tendances actuelles ;
- Les plus reniflées aujourd’hui ;
- Séries à dévorer ;
- Blockbusters à quatre pattes ;
- Parce que vous avez regardé Jurassic Bark ;
- Comédies qui donnent la patte ;
- Univers sombres, museaux humides ;
- Ma liste.

Le hero peut mettre en avant **Breaking Dog**. Les rangées doivent contenir assez d’éléments pour rendre les carrousels utiles.

## 7. Génération obligatoire des images

Utilise l’outil de génération d’images de ChatGPT disponible dans l’environnement pour produire les assets du site. Ne récupère aucune affiche sur Internet et n’utilise aucun hotlink.

Crée réellement :

- une affiche verticale originale au ratio `2:3` pour chacune des 40 œuvres ;
- au minimum trois backdrops horizontaux `16:9`, dont un pour **Breaking Dog** ;
- quatre avatars de profils canins ;
- si utile, un fond subtil ou une illustration supplémentaire pour le faux lecteur.

Contraintes communes aux affiches :

- rendu cinématographique premium, détaillé et cohérent sur toute la collection ;
- chiens comme personnages principaux, avec races, costumes, décors et ambiances adaptés à chaque parodie ;
- composition évocatrice permettant de comprendre immédiatement la référence sans recopier l’affiche originale ;
- aucune ressemblance exacte avec un acteur réel ;
- aucun logo de studio, aucune marque, aucun watermark et aucun texte parasite généré dans l’image ;
- ne demande pas au modèle d’image d’écrire les titres : superpose les titres proprement avec le frontend si nécessaire ;
- fichiers optimisés, convertis en WebP ou AVIF et enregistrés localement dans une arborescence claire comme `public/assets/posters`, `public/assets/backdrops` et `public/assets/profiles` ;
- noms de fichiers stables, descriptifs et utilisés dans le catalogue TypeScript.

Si les générations doivent être réalisées en plusieurs appels, poursuis jusqu’à ce que les 40 affiches soient présentes. Ne remplace pas cette étape par des dégradés, des emojis ou des placeholders définitifs. Ajoute seulement un fallback CSS élégant en cas d’échec ponctuel de chargement dans le navigateur.

## 8. Fonctionnalités frontend

Même si le site est statique, implémente de vraies interactions côté navigateur :

- sélection et mémorisation locale du profil ;
- recherche instantanée dans les 40 œuvres ;
- filtres `Séries`, `Films`, `Nouveautés` et retour à l’accueil ;
- ajout et retrait de `Ma liste`, mémorisé dans `localStorage` ;
- carrousels accessibles à la souris, au trackpad, au toucher et au clavier ;
- ouverture d’une modal de détail depuis une vignette ou `Plus d’infos` ;
- fermeture de la modal avec un bouton, un clic extérieur ou la touche `Échap` ;
- bouton `Lecture` ouvrant un faux lecteur plein écran élégant ;
- le faux lecteur affiche quelques secondes d’animation puis une phrase différente selon l’œuvre, par exemple : `Votre chien a mangé la bande passante.` ;
- bouton de volume visuellement fonctionnel sur le hero, sans lecture automatique de son ;
- skeletons ou animation de chargement très brève pour renforcer l’illusion d’une vraie plateforme ;
- états de focus visibles et navigation clavier correcte ;
- respect de `prefers-reduced-motion`.

Les interactions ne doivent appeler aucun serveur. `localStorage` est autorisé uniquement pour les préférences locales.

## 10. Responsive et qualité visuelle

- grand écran : navigation complète, hero très large, six vignettes environ par rangée ;
- tablette : réduction progressive des espacements et quatre vignettes environ ;
- mobile : navigation simplifiée, hero lisible, deux vignettes environ, contrôles tactiles et aucune zone coupée ;
- aucune barre de défilement horizontale globale ;
- textes et boutons toujours contrastés ;
- images chargées paresseusement hors du hero ;
- dimensions d’images définies pour limiter les décalages de mise en page ;
- animations fluides sans détériorer les performances.

## 12. Déploiement Railway

Le projet doit être immédiatement déployable sur Railway.

Fournis une configuration robuste, de préférence :

- `Dockerfile` multi-stage : build Node, puis service statique Nginx ;
- configuration Nginx incluant la compression, le cache long des assets hashés et le fallback vers `index.html` ;
- écoute correcte du port attendu par Railway, avec utilisation de la variable `PORT` si nécessaire ;
- fichier `railway.json` si cela améliore la détection et le démarrage ;
- `.dockerignore` et `.gitignore` adaptés ;
- healthcheck HTTP sur `/` ;
- aucune variable secrète requise.

Ajoute dans le README les commandes exactes pour le développement, le build local, le test du conteneur et le déploiement depuis un dépôt GitHub connecté à Railway.
